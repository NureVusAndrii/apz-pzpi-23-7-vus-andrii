2 ЗАВДАННЯ

Студент повинен обрати одну зі складних сучасних програмних систем для аналізу її архітектури. Це може бути операційна система, вебсервіс, хмарна платформа, середовище розробки, база даних, розподілена система або інша масштабна програмна платформа.
Необхідно підготувати доповідь, у якій слід розкрити архітектурні підходи, принципи побудови системи, взаємодію її компонентів та особливості масштабування. Також потрібно проаналізувати використані архітектурні стилі та технологічні рішення.
Доповідь повинна супроводжуватись:
•	Описом призначення та основних функцій обраної програмної системи; 
•	Аналізом архітектури системи та її ключових компонентів; 
•	Поясненням взаємодії між окремими модулями або сервісами; 
•	Описом принципів масштабування, відмовостійкості та продуктивності системи; 
•	Аналізом використаних архітектурних стилів і технологій; 
•	Прикладами програмних рішень або фрагментів коду (за наявності); 
•	Висновками щодо ефективності та особливостей обраної архітектури. 
Студент повинен надати докладний аналіз архітектури обраної системи, оформити презентаційні матеріали та представити результати своєї роботи викладачу.
 
3 ОПИС ВИКОНАНОЇ РОБОТИ

3.1 Вибір системи для розгляду
Discord є однією з найвідоміших сучасних платформ для онлайн-спілкування, яка підтримує текстові повідомлення, голосові дзвінки, відеоконференції та роботу великих спільнот у режимі реального часу.
Система одночасно обслуговує мільйони користувачів по всьому світу та повинна забезпечувати високу швидкість обміну повідомленнями, стабільність голосового зв’язку та постійну доступність сервісу. Це все робить цікавим розгляд її архітектурної системи, компонентів та їх взаємодії, механізмів масштабування тощо.

3.2 Основна інформація та вимоги до системи
Discord – це платформа для комунікації, створена у 2015 році. Спочатку вона орієнтувалася на геймерів, але згодом стала універсальним середовищем для навчання, роботи та онлайн-спільнот.
Система побудована за принципом серверів або спільнот, де користувачі можуть створювати текстові та голосові канали. Discord підтримує роботу у режимі реального часу, тому повідомлення та голосові дані передаються майже без затримок.
Основними вимогами до архітектури Discord є:
•	висока продуктивність;
•	підтримка мільйонів одночасних підключень;
•	масштабованість;
•	мінімальна затримка передачі даних;
•	відмовостійкість.

Для реалізації цих вимог Discord використовує сучасні підходи до побудови розподілених систем, мікросервісну архітектуру, балансування навантаження та окремі сервіси для різних типів функціональності.

3.3 Загальна архітектура системи
Архітектура Discord базується переважно на мікросервісному підході. Це означає, що система складається з великої кількості окремих сервісів, кожен із яких відповідає за конкретну функцію. Наприклад, окремо працюють сервіси авторизації, повідомлень, голосового зв’язку та обробки медіа.
Перевага такого підходу полягає у незалежному масштабуванні сервісів. Якщо навантаження на голосові сервери зростає, можна масштабувати лише їх, не змінюючи інші компоненти системи.
Також Discord використовує клієнт-серверну архітектуру. Клієнтські застосунки, а саме браузер, десктопна та мобільна версії взаємодіють із бекендом через REST API та WebSocket-з’єднання. REST API використовується для звичайних HTTP-запитів, а WebSocket забезпечує постійний зв’язок у режимі реального часу.
Крім цього, у Discord активно застосовується подієво-орієнтована архітектура, де сервіси обмінюються подіями через внутрішні брокери повідомлень.

3.4	Основні компоненти Discord
Архітектура Discord складається з багатьох взаємопов’язаних компонентів. Перший важливий компонент – це API Gateway. Це центральна точка входу для клієнтів. Саме через неї проходять HTTP-запити та WebSocket-підключення користувачів.
Другий компонент – це сервіс авторизації. Він відповідає за вхід користувачів, токени доступу та безпеку акаунтів.
Окремо працює Message Service, тобто сервіс обробки повідомлень. Він відповідає за зберігання повідомлень, історію чатів та синхронізацію між клієнтами.
Voice Service обробляє голосовий зв’язок та відеоконференції. Для мінімізації затримок голосові сервери розташовуються у різних регіонах світу.
Також Discord використовує бази даних, кешування та CDN-сервери для зберігання медіафайлів. Наприклад, для швидкого доступу до часто використовуваних даних застосовується Redis, а для масштабованого зберігання повідомлень – PostgreSQL та Cassandra.

3.5	Взаємодія компонентів системи між собою
Коли користувач відкриває Discord, клієнт надсилає запит до API Gateway. Після авторизації система видає токен доступу та встановлює WebSocket-з’єднання для роботи в режимі реального часу.
Наприклад, коли користувач надсилає повідомлення, клієнт формує HTTP або WebSocket-запит до Message Service. Сервіс перевіряє права доступу, зберігає повідомлення у базі даних та надсилає подію іншим користувачам каналу.
Для голосового зв’язку клієнт підключається до Voice Server. Голосові дані передаються через UDP-протокол для зменшення затримок.
Між сервісами постійно відбувається внутрішній обмін повідомленнями та подіями. Це дозволяє компонентам працювати незалежно один від одного та швидко реагувати на зміни у системі.
Така архітектура забезпечує високу швидкість роботи та можливість одночасного обслуговування великої кількості користувачів

3.6	Огляд програмної реалізації системи на конкретному прикладі
Discord активно використовує REST API та WebSocket-з’єднання. Нижче наведений спрощений приклад HTTP-запиту для надсилання повідомлення через Discord API мовою Python, оскільки саме Python часто використовується для ботів та інтеграцій Discord.

 1  import requests
 2  
 3  TOKEN = "Bot TOKEN"
 4  CHANNEL_ID = "123456789"
 5  
 6  url = f"https://discord.com/api/v10/channels/{CHANNEL_ID}/messages"
 7  
 8  headers = {
 9      "Authorization": TOKEN,
10      "Content-Type": "application/json"
12  }
13  
14  data = {
15      "content": "Hello from Discord API!"
16  }
17  
18  response = requests.post(url, json=data, headers=headers)
19  
20  print(response.json())

У цьому прикладі клієнт надсилає POST-запит до REST API Discord для створення нового повідомлення у каналі. Для роботи в режимі реального часу Discord використовує WebSocket Gateway, через який клієнти отримують нові повідомлення, зміни статусів та інші події без постійного надсилання HTTP-запитів.

 1  const WebSocket = require("ws");
 2  
 3  const gateway = new WebSocket("wss://gateway.discord.gg/?v=10&encoding=json");
 4  
 5  gateway.on("open", () => {
 6      console.log("Connected to Discord Gateway");
 7  });
 8  
 9  gateway.on("message", (data) => {
10      const event = JSON.parse(data);
11  
12      // Отримання нових повідомлень
13      if (event.t === "MESSAGE_CREATE") {
14          console.log("New message:", event.d.content);
15      }
16  });
17  
18  gateway.on("close", () => {
19      console.log("Connection closed");
20  });

У цьому прикладі використовується WebSocket Gateway Discord.
Клієнт встановлює постійне з’єднання із сервером та отримує події у режимі реального часу.
Коли у каналі з’являється нове повідомлення, сервер надсилає подію MESSAGE_CREATE, після чого клієнт одразу отримує текст повідомлення без повторних HTTP-запитів.
Саме завдяки WebSocket Discord забезпечує миттєве оновлення чатів, статусів користувачів та голосових подій.

3.7	Масштабування та стійкість архітектури
Discord обслуговує десятки мільйонів активних користувачів, тому масштабованість є критично важливою.
Для цього система використовує горизонтальне масштабування. Це означає, що замість збільшення потужності одного сервера додаються нові сервери. Навантаження між ними розподіляється за допомогою балансувальників навантаження.
Також Discord активно використовує кешування через Redis, що дозволяє зменшити кількість звернень до бази даних та пришвидшити обробку запитів.
Для забезпечення надійності дані реплікуються між кількома серверами та дата-центрами. Якщо один сервер виходить з ладу, система автоматично перенаправляє користувачів на інший.
Важливу роль відіграє моніторинг системи. Discord постійно аналізує навантаження, помилки та затримки, щоб швидко реагувати на можливі проблеми та забезпечувати безперервну роботу сервісу.

3.8	Переваги та недоліки архітектури Discord
	Мікросервісна архітектура Discord має багато переваг. Вона дозволяє незалежно масштабувати окремі компоненти, спрощує оновлення сервісів та забезпечує високу відмовостійкість. Також система добре підходить для роботи у глобальному масштабі.
	Використання WebSocket забезпечує майже миттєву доставку повідомлень та синхронізацію клієнтів у режимі реального часу.
	Проте така архітектура має і недоліки. По-перше, мікросервісна система є значно складнішою у підтримці та моніторингу. По-друге, взаємодія між великою кількістю сервісів створює додаткові затримки та потребує складної системи балансування й оркестрації.
	Також виникають труднощі із забезпеченням консистентності даних у розподіленому середовищі. Незважаючи на це, для масштабної платформи рівня Discord переваги такого підходу значно переважають його недоліки.
 
ВИСНОВКИ

У результаті виконання практичного заняття було сформовано розуміння про внутрішню структуру та архітектурні підходи сучасних складних програмних систем на прикладі Discord. 
Виконана робота показала, що Discord є прикладом сучасної масштабованої розподіленої системи, побудованої на основі мікросервісної архітектури.
Система використовує REST API, WebSocket-з’єднання, балансування навантаження, кешування та горизонтальне масштабування для забезпечення швидкої та стабільної роботи.
Завдяки поділу на окремі сервіси Discord може ефективно підтримувати мільйони одночасних користувачів та швидко розширювати функціональність платформи.
Архітектурні рішення Discord демонструють, наскільки важливими є масштабованість, відмовостійкість та правильна організація взаємодії компонентів у сучасних програмних системах. Саме тому Discord можна вважати одним із вдалих прикладів побудови високонавантаженої клієнт-серверної платформи.
